# تفاصيل الطلب — Ahmad UI

أساس b0abce1، root مشرف ومنفذ، فرع ahmad-ui، READY_FOR_REVIEW. المرجع صورة المستخدم ذات نصفي الصفحة. لا تغيير main أو Auth أو Domain/Data أو عقود HTTP أو مصادر البيانات.

## النتيجة

صفحة واحدة قابلة للتمرير: رقم الطلب وحالته وتاريخ إنشائه، فئة المركبة وصورتها الموجودة، خريطة بعرض البطاقة ثم نقطتا الانطلاق والوصول، المسافة والمدة، السائق، الأجرة المسجلة والكوبون وطريقة الدفع وحالته. حُذف أي قسم لتسلسل «توقيت الرحلة» ولم نضف رابط «تفاصيل أدق لرحلتك». التاريخ في رأس الطلب باقٍ كما بالمرجع؛ المواعيد الزمنية المنفصلة لم تعد تظهر في تفاصيل الطلب.

أعيد استخدام صور المركبات وأيقونات address_pin/account/rating/payment/wallet، وبقيت أدوات التنقل والأفعال على عناصر Material المهيأة بالثيم. الدعم زر واضح، إعادة الطلب إجراء ثانوي، والتقييم رابط إلى نموذج التقييم الموجود بنفس tripId؛ لم نكرر نموذج التقييم أو نغيّر قواعد الإرسال. بقي إلغاء/متابعة الرحلة للحالات المسموحة.

المُنسّق المشترك يعرض SYP برمز ل.س المحلي، ويترجم فئات المركبات المعروفة بدل معرّفات comfort/van/motorbike الخام. باقي العملات والقيم الرقمية لم تتغير.

## حدود البيانات

لا يحمل TripBookingInput مدة/مسافة محفوظتين أو أجرة أصلية ومبلغ خصم أو حالة تسديد. لذلك تظهر غير متوفرة/غير مؤكدة، ولا يُفترض دفع الرحلة من اكتمالها، ولا تُحسب قيمة خصم من اسم الكوبون. بيانات السائق تظهر من live.driver عندما تتوفر؛ السجل الاصطناعي القديم لا يملكها ويعرض ذلك بوضوح. لا صور شخصية مختلقة أو أرصدة وهمية.

الخريطة تستخدم المحرك والمواقع الفعلية الموجودين. لا نرسم خط طريق مختلق إذا لم يرجع مزود المسار هندسة الطريق. هذه حدود البيانات الحالية؛ استكمال حقول الإيصال المحفوظة يحتاج مهمة عقد/تخزين مستقلة.
