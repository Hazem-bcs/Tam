# متابعة الكابتن ومصداقية المسار

أُنجز توجيه الكاميرا إلى السيارة ومتابعتها في المحركين native/raster، مع إيقاف المتابعة بالسحب وزر لإعادتها. الكاميرا تراعي مساحة اللوحة السفلية وتقليل الحركة. أوامر الكاميرا الأصلية محدودة بنحو5/ثانية لتجنب إلغاء الأنيميشن كل إطار. تستقر الكاميرا على آخر نقطة أيضًا عند توقف التحديثات.

المسار الاصطناعي يصرّح الآن `road_aligned:false` في بيانات المحاكاة ولا يُرسم كطريق فعلي. ما زالت حركة المحاكاة اصطناعية حتى توصيل مزود routing؛ إخفاء الخط لا يحل مطابقة الطرق. سُئل المستخدم مبكرًا إن أراد OSRM عامًا مؤقتًا أو رابط الباك إند؛ لم يصل اختيار أثناء هذه الدفعة، لذلك لم تُرسَل إحداثياته لخدمة عامة ولم يُفعّل مزود جديد. هذا الجزء مطلوب لإكمال الطلب الثاني وما زال معلّقًا على اختيار المزود.

التحقق: `flutter test --no-pub test/features/maps test/features/active_trip/active_trip_contract_test.dart test/features/active_trip/tracking_geometry_test.dart`: 102/102 ناجحة. تحليل سطح الخرائط والتتبع المعني: لا ملاحظات. تنسيق الملفات المملوكة وdiff-check ناجحان. لم يُعد الفحص العام للمشروع خارج نطاق هذه الدفعة.

Android: build/install/run ناجحة على emulator-5554. طلب وهمي فعلي، ثم [صورة متابعة السائق](android-follow.png)؛ راجعت موضع السيارة وزر المتابعة وغياب الخط الاصطناعي. لا تقرر الصورة أن السيارة تسير على طريق حقيقي؛ هذا يعتمد على مزود لم يُربط بعد.

أضاف عميل آخر branding في8842b19 أثناء العمل؛ حُفظ كاملًا، ولم تُعدّل ملفاته في هذا التغيير. لا main أو push أو CI. ملفات المحرك الأصلية تتجاوز300 سطر سابقًا؛ أبقينا المتابعة مع دورة حياة الكاميرا/الإيماءات القائمة لمنع فصل ملكية غير متماسك أو إعادة هيكلة خارج المهمة.
