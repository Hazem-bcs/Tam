# نافذة الاسم والصورة — Ahmad UI

Task: AUI-04-PROFILE-POPUP-20261117؛ root مشرف ومنفذ، أساس `5fe5ec6`، فرع `ahmad-ui`. الحالة READY_FOR_REVIEW؛ main لم يتغير.

زر التعديل يفتح نافذة سفلية فوق التطبيق وشريط التنقل، فيها صورة قابلة للاختيار من معرض النظام، الاسم، الحفظ والإلغاء. المسودة منفصلة عن القيمة المحفوظة؛ الإلغاء/الرجوع مع تعديلات يطلب التأكيد، والفشل يبقي المسودة لإعادة المحاولة. الصورة وحدها تكفي لتفعيل الحفظ. يظهر الاسم المحفوظ أيضًا في بطاقة الضيف، مع بقاء وصفه «أنت تتصفح كضيف»؛ لا تتغير هوية Auth أو الصلاحيات.

الاختيار عبر عقد ProfilePhotoPicker ومحول data، محقون عبر get_it في composition root. أضيف image_picker 1.2.4 وإفصاح استخدام الصور لـiOS، دون كاميرا أو أذونات مكتبة عامة في Android. الصورة مصغرة وPNG بحد5MiB، تُنسخ إلى ذاكرة المستودع كبيانات غير قابلة للتعديل. المرجع التقني: [توثيق Flutter Image Picker](https://pub.dev/packages/image_picker).

## حدود الحفظ

الاسم والصورة محفوظان ذريًا في Mock أثناء الجلسة الحالية وفتح الصفحة مجددًا؛ يُمسحان مع نهاية الجلسة/إعادة تشغيل العملية. لا رفع صورة، لا اعتماد backend، ولا إنشاء مستخدم موثق للضيف. API mode يبقى غير متاح بلا نجاح محاكى. عقد HTTP v1 وPostman والfixtures لم تتغير؛ avatarBytes معامل محلي اختياري لا يرسل إلى الخادم. تحديث التوثيق ضمن docs/api/settings يوضح ذلك.

قتل عملية Android أثناء المعرض لا يستعيد المسودة؛ لم نفعّل lost-data restoration أو استمرار الصورة بعد إعادة تشغيل العملية. iOS لم يُبنَ أو يُفحص على هذه الآلة.
