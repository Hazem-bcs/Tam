# Ahmad UI — حزمة برومبتات الوكلاء + الصور (نسخة 1)

> **طريقة الاستخدام:** افتح محادثة مستقلة لكل وكيل، انسخ **نص البرومبت الخاص به بالكامل** من القسم المقابل، وأرفق الصورة/الصور الأصلية المذكورة هناك كـ**صور مرفقة** (وليس مجرد ذكر اسم الملف). إذا لم تسمح بيئة الوكيل بإرفاقها، أعطه الرابط المباشر وتحقق أنه استطاع رؤيتها فعلاً. لا ترسل صور السائق UI-14 وUI-16…UI-24 إلى وكلاء العميل.
>
> **المشرف A20 هو محادثة ChatGPT هذه**؛ المستخدم ينقل إليه تقارير الوكلاء ولا نفترض اتصالاً مباشراً بين جلساتهم.
>
> **حالة اليوم:** نقطة الانطلاق من `main` هي `ffad266d4de544d7634bec79ac25587584987416`، وفرع `ahmad-ui` موجود بالفعل لكن لم يبدأ تنفيذ الواجهات. احصل على `FROZEN_AHMAD_SHA` من A20 قبل تغيير كود الـ12 شاشة.

## ترتيب الانطلاق (لا نضيّع وقت أحد)

**ابدأ فوراً بالتوازي:** A13 (الهوية المركزية)، A14 (جرد/إنتاج الأصول)، A15 (حركات)، A16 (Cloud CI)، A17–A19 (قوائم التدقيق). **وفي الوقت نفسه** أرسل A01–A12 إلى مرحلة الاكتشاف: قراءة صورهم، تحليل كود الواجهة وتحديد مكوّناتها وطلبات الأصول، لكن **لا يكتبون إلى كود الإنتاج** حتى اعتماد نسخة هوية أحمد. بعد اعتماد A13 يعلن A20 `FROZEN_AHMAD_SHA` ويطلق الـ12 مطوراً بالتوازي. A20 يدمج أعمالهم على `ahmad-ui` فقط، بعد مراجعة ولقطات حقيقية.

**الحالات:** `ONBOARDING -> DESIGN_ANALYSIS -> WAITING_FOR_FROZEN_SHA -> IMPLEMENTING -> PR_REVIEW -> APPROVED_AT_SHA -> INTEGRATED`.

**سياسة الأصول:** إذا كانت صورة مرجع WhatsApp تحتوي أيقونة/سيارة، ابحث أولاً عن الأصل الموجود في المستودع. إن لم يوجد، قدم طلب Asset بمواصفات الاتجاه والشفافية والدقة واللون والمنظور والترخيص. يستطيع الوكيل توليده أو رسم SVG/WebP أصلي إذا كانت لديه وسيلة حقيقية، وإن لم تكن لديه يقدم Prompt إنتاج محدداً للمستخدم؛ ممنوع الادعاء بتوليد ملف لم يُنتج أو إعادة تدوير قصاصة منخفضة الجودة وتسميتها أصل 3D. كل أصل في مجلد نطاقه، والمالك A14 يراجع اتساق الأسلوب.
