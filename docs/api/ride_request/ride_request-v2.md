# عقد طلب الرحلة v2 — الدفع والكوبون

حالة العقد: مقترح إضافي متوافق مع v1، الباكند غير موصول. المسارات HTTP تبقى
`POST /ride-quotes` و`POST /trips` نسبة إلى `base_url` المنتهي بـ`/api/v1`؛
مثل `https://api.example.invalid/api/v1/ride-quotes`، دون تكرار `/v1`.
رقم v2 هنا نسخة الوثيقة/العقد.
لا تعني الواجهة أو أمثلة المحفظة وصولًا إلى رصيد أو تنفيذ دفع حقيقي.

## عرض السعر

يرسل المسار وفئة المركبة والموعد UTC حسب v1، مع:
- `payment_method`: `cash | wallet`؛ غيابه في أمثلة v1 القديمة يعني cash فقط.
- `coupon_code`: اختياري؛ أحرف عربية/تشكيل أو A–Z وأرقام وشرطة/underscore بطول1–32، وفق تطبيع [كوبونات v1.1](../ride_coupons/ride_coupons-v1.md). يحفظ الرمز العربي في السعر والحجز والاستعادة.
  العميل يطبّع المسافات الطرفية وحالة الأحرف؛ الخادم يقرر الأهلية والحسم.

يرد الخادم بنفس payment_method وcoupon_code المطبّع، و`fare` المبلغ النهائي،
و`discount` كـMoney عند تطبيق كوبون فقط، بالعملة والوحدة نفسيهما. السعر قبل
الحسم =fare+discount. لا يحتسب UI النسبة أو يختلق سعرًا على فئة غير مسعّرة.
الأرقام بأصغر وحدة صحيحة؛ لا float للنقود. غياب code/discount معًا يدعم v1؛
تعارضهما أو طريقة دفع/عملة/وحدة غير معروفة يؤدي إلى INVALID_RESPONSE.

مقارنة الفئات تستخدم حاليًا طلب quote مستقل لكل فئة مدعومة (standard, comfort,
van, motorbike) مع intent مطابق. فشل فئة غير مختارة لا يمنع الفئة المتاحة؛
تغيير المسار أو الموعد أو الدفع أو الكوبون يبطل الكتالوج. الفئات الإضافية تحتاج
توسيع معرّفات العقد/الكتالوج؛ التخطيط الأفقي لا يفترض أربع خانات أو عرضًا ثابتًا للشاشة.
النتائج المتأخرة لمسودة قديمة لا تستبدل أحدث intent، وعرض منتهي لا يُؤكّد.

## التأكيد والمال

`POST /trips` يرسل quote_id وIdempotency-Key؛ لا يرسل سعرًا محسوبًا من UI.
الخادم يربط العرض بفئة المركبة والدفع والكوبون ويعيدهما في الرحلة.
يجب تثبيت الحجز وخصم المحفظة وحسم/استهلاك الكوبون ذريًا وفق أهلية الخادم.
إعادة المفتاح نفسه لنفس العرض ترجع الرحلة ذاتها دون خصم أو حسم مكرر.
المفتاح نفسه مع intent آخر يعيد IDEMPOTENCY_CONFLICT. لا يعيد الخادم
الطلب كـcash تلقائيًا عند فشل wallet، ولا يستبدل كوبونًا مرفوضًا بسعر صامت.
الفشل القطعي COUPON_INVALID/PAYMENT_UNAVAILABLE/WALLET_INSUFFICIENT يحتاج
اختيارًا/عرضًا جديدًا؛ فشل الاتصال بعد إرسال غير محسوم يعيد المحاولة بالمفتاح الأصلي.

## الأخطاء والرسائل

- COUPON_INVALID /422: كوبون غير صحيح/منتهي/غير مؤهل، حقل واضح وتصحيح أو إزالة.
- PAYMENT_UNAVAILABLE /422: الدفع المختار غير متاح، اختيار cash صريح أو إعادة طلب.
- WALLET_INSUFFICIENT /422: الرصيد غير كافٍ؛ لا تحويل تلقائي إلى cash.
- جميع401/403/409/503/expiry/schedule في v1 تبقى نافذة. API يتطلب الجلسة الحقيقية.

## المحاكاة والتسليم

المحاكاة في data/mock فقط: TAM10 يحسم10% من السعر الأصلي مع تقريب صحيح للأسفل؛
هذا fixture للتطوير، وليس كوبونًا تجاريًا. walletAvailable=false يثبت فشل المحفظة.
المحاكاة تحفظ طريقة الدفع والكوبون والسعر في Trip المحلي المشترك؛ لا رصيد ولا
ledger ولا دفع حقيقي. API implementation يبقى UnavailableRideRequestRepository،
ولا fallback إلى mock. fixtures quote_wallet_coupon_* وtrip_wallet_coupon_success
وأمثلة أخطاء error_coupon/error_payment/error_wallet_insufficient متاحة للاستيراد.
مجموعة Postman v2 مرفقة، ولم تُشغّل أي طلبات حية.
