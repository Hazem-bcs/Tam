# تم — حزمة الدعم والمحتوى القانوني v1

الحالة: **عقد مقترح للتنفيذ من مطور الباكند، غير متحقق مع خادم حي**.
التطبيق يستخدم محاكاة محلية؛ لا تُرسل الطلبات حاليًا إلى موظفين. API mode
يفشل صراحة بـSERVICE_UNAVAILABLE حتى يتوفر محول الشبكة، دون الرجوع للمحاكاة.

ابدأ بقراءة [العقد](support-v1.md)، ثم استورد
`support-v1.postman_collection.json` كـCollection v2.1. اضبط `base_url`
و`access_token` و`trip_id` و`ticket_id`. العنوان example.invalid توضيحي ولا
توجد أسرار. المحتوى القانوني يستخدم No Auth عمدًا؛ طلبات الدعم ترث Bearer.

1. اطلب الفئات العامة أو فئات رحلة يملكها الحساب.
2. أرسل بلاغًا بالفئة والنص ومعرّف `client_request_id` جديد عشوائي آمن.
   للدعم العام احذف trip_id أو أرسله null واختر فئة لا تتطلب رحلة.
3. عند فقد الرد أعد المعرّف والبيانات نفسها؛ لا تُنشئ معرّفًا جديدًا.
4. افتح القائمة ثم التفاصيل. حد الصفحة20؛ فعّل cursor عند متابعة الصفحة.
5. الشروط والخصوصية تعيدان data:null ما دام النص المعتمد غير منشور.
   لا تولّد نصوصًا قانونية ولا تُضف إقرار موافقة في Auth ضمن هذا العقد.

الأمثلة محفوظة في `examples/` ومختبرة بـSupportWireMapper ومقارنة بالمحاكاة.
أمثلة الترقيم25 طلبًا مصطنعًا؛ حالتا in_progress/resolved أمثلة استجابة
للخادم فقط، ولا تحول المحاكاة الطلب إلى حالة معالجة بشرية تلقائيًا.

الاختيار المركزي: `SUPPORT_DATA_MODE` يرث DATA_MODE، و
`SUPPORT_MOCK_SCENARIO=success|empty|offline|lost_response`.
المصدر MockTripStore المشترك؛ الطلبات المقبولة تعيش داخل جلسة المستودع
وتُمسح بالخروج. المسودة والطلب غير المحسوم مرتبطان بعمر الصفحة، دون outbox
دائم. الخادم الحقيقي مسؤول عن حفظ الطلبات للحساب، والتفويض وidempotency.

فُحصت JSON وأمثلة الطلبات والاستجابات آليًا؛ لم يُنفذ استيراد فعلي داخل
Postman ولم تُرسل طلبات حية. النص القانوني النهائي وربط HTTP ما زالا معتمدين
على تسليم الباكند والمحتوى المعتمد. الواجهة مبدئية ضمن المرحلة الأولى.
