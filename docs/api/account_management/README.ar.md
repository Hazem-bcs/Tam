# تسليم إدارة الحساب — v1

حزمة مقترحة لتنفيذ Laravel؛ لا خدمة متصلة أو جلسة مصادقة وهمية.
استورد account_management-v1.postman_collection.json واقرأ وصف المجموعة:
يحتوي [العقد العربي](account_management-v1.md) كاملًا وأمثلة الطلبات والأخطاء.

اضبط base_url وaccess_token الحقيقيين. اختر بدء تغيير الرقم أو بدء الحذف
بمعرف operation_id جديد آمن، ثم انسخ challenge_id وrecovery_token من الرد.
لا تضع grant في URL ولا تشاركه. أدخل otp_code المستلم ثم أكد نفس الغرض.
الأمثلة اصطناعية؛ لا SMS حقيقي في المحاكاة.

تمنع الأهلية وجود رحلة غير منتهية؛ الحذف يحتاج تأكيدًا واضحًا في Flutter.
بعد فقد الرد لا تولد operation_id جديدًا؛ اقرأ receipt بالـgrant أو أعد
نفس Confirm. أول تنفيذ يتطلب Bearer؛ grant لا ينفذ عملية جديدة، بل يحسم
عملية واحدة بعد فقد ردها أو إبطال الجلسة. لا يعيد ملف الحساب أو هاتفه.

المصدر الافتراضي mock، والسيناريو success/offline/lost_response/phone_in_use
مركزي. نتائج المحاكاة تمسح بالخروج ولا تغير مستخدمًا على خادم. OTP الأول
123456 ثم654321 بعد إعادة الإرسال الأولى، للاختبار المحلي فقط.
العقد يثبت الوقت والمحاولات والقفل وidempotency وفحص الملكية والرحلات داخل
معاملة التنفيذ. لا نصوص قانونية أو سياسة احتفاظ مخترعة ضمن هذا التسليم.

فحص JSON وPostman والأمثلة والـmapper والمحاكاة آلي؛ لم تُختبر SMS أو
خدمة حية أو استيراد Postman فعلي. التدفق لا يغيّر عقد Auth الأصلي أو تجاوز
OTP الدخول المؤقت. grant لا يصل إلى BLoC state أو logs؛ يحفظه محول API في data.
