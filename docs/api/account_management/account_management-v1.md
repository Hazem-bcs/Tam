# تم — إدارة رقم الحساب وحذفه، عقد v1

الحالة: مقترح للتنفيذ، غير متصل بخادم حي. هذا امتداد مستقل عن مسارات Auth
الستة؛ لا يستخدم تحقق عملية حساسة لتسجيل دخول أو إصدار جلسة جديدة.
base_url يشمل /api/v1. النجاح data، والفشل error.code وmessage.ar/en.
كل الأوقات ISO8601 UTC Z بتقويم صحيح. المعرفات opaque وغير فارغة.

## التدفقات والقرارات

تغيير رقم سوري: إدخال الجديد، OTP للرقم الجديد، تأكيد ثم إنهاء الجلسة.
الحذف: تأكيد صريح من المستخدم، OTP لرقمه الحالي، تنفيذ الحذف ثم إنهاء
الجلسة. لا دمج حسابين ولا تغيير رقم دون تحقق. المحفظة والدفع والكوبونات
مؤجلة. ليست هذه سياسة احتفاظ قانونية؛ النصوص المعتمدة مسؤولية صاحب المنتج.

يمنع الخادم العمليتين أثناء أي رحلة غير منتهية، بما فيها scheduled.
يفحص ذلك عند إنشاء التحقق ومجددًا داخل معاملة التنفيذ؛ لا يعتمد على UI.
هذه سياسة الإصدار الأول المتبعة في المحاكاة، وقابلة للتعديل بالتنسيق.
الضيف والدخول المؤقت ليسا جلسة API. المحاكاة تحاكي ملكية الرقم المدخل محليًا
ولا تنشئ حسابًا أو توكنًا موثقًا. تجاوز OTP الدخول المؤقت لا ينطبق على هذه العمليات.

## العمليات

| الفعل | Repository | HTTP |
|---|---|---|
| أهلية الإدارة | eligibility | GET /me/account/eligibility |
| بدء تحقق تغيير أو حذف | start | POST /me/account/challenges |
| إعادة إرسال | resend | POST /me/account/challenges/{challenge_id}/resend |
| تأكيد العملية | confirm | POST /me/account/challenges/{challenge_id}/confirm |
| حسم فقد الرد | operation | GET /account/operations/{operation_id} |

Accept:application/json؛ Content-Type:application/json لطلبات POST.
أول أربع عمليات تتطلب Bearer صالحًا وملكية الحساب والتحقق. عملية الحسم
الأخيرة لا تتطلب جلسة حساب، لكنها **ليست عامة بلا اعتماد**: تحتاج
X-Operation-Token سريًا محدود الصلاحية بالعملية نفسها. التأكيد يحتاجه كذلك.
إعادة تأكيد عملية مكتملة بعد إبطال الجلسة يسمح بها فقط لاسترجاع نتيجتها
بنفس token والعملية والتحقق والحمولة، دون أي تعديل جديد. أول أثر يتطلب
Bearer صالحًا دائمًا؛ recovery token وحده لا ينفذ حذفًا أو تغييرًا.

GET eligibility: data.phone_e164 مطلوب string سوري canonical؛
data.active_trip_ids قائمة معرفات فريدة للرحلات غير المنتهية. الخادم الحقيقي
لا يعيد guest success؛ مثال phone_e164:null يصف أهلية المحاكاة للضيف فقط،
ولا يوجد نجاح كهذا محفوظ في طلب Postman الخادمي.

POST challenge body: operation_id مطلوب `[A-Za-z0-9_-]{16,128}`؛ العميل يولد
48hex من مصدر آمن. purpose مطلوب change_phone|delete_account.
new_phone_e164 مطلوب لتغيير الرقم بصيغة +9639 ثم8 أرقام، ويجب أن يختلف
عن الحالي وألا يخص حسابًا آخر. للحذف يغيب أو يكون null. يثبت الخادم
هوية الحساب والهدف والغرض في التحقق، لا يقبل تبديلها عند التأكيد.

200 data: challenge_id وoperation_id وpurpose وphone_e164 (هدف OTP)،
expires_at وresend_at، attempts_remaining:int0..5، revision:int≥1،
وrecovery_token:64hex عشوائي آمن. الأخير اعتماد استعادة، يخزنه محول API
خصوصيًا في data خلال عمر الصفحة؛ لا tokens في Cubit state أو logs أو URL.
ممنوع إعادة استخدامه للوصول للملف أو الرحلات أو بدء عملية أخرى.

رمز OTP ست خانات، صالح5 دقائق، وإعادة الإرسال بعد30 ثانية. خمسة أخطاء
تفرض قفل15 دقيقة على الحساب/الهدف عبر التحققات الجديدة أيضًا. الخادم
يطبق حدود إرسال مستقلة حسب الحساب/الهدف/المصدر؛429 وRetry-After للرفض.
هذه حدود مقترحة مثبتة في AccountPolicy وتحتاج تنسيقًا عند تغييرها.
الوقت والمحاولات مصدرهما الخادم؛ العميل لا يقرر نجاح الرمز من الساعة.

POST resend body: request_id آمن بنفس نمط operation_id، ثابت عند إعادة
محاولة الإرسال نفسها. يظل challenge_id ثابتًا وترتفع revision وتتجدد
المواعيد والمحاولات ضمن حدود المعدل. كل إعادة إرسال ناجحة تبطل الرمز السابق.
إعادة نفس request_id للتحقق نفسه لا ترسل SMS جديدًا ولا تعيد ضبط الساعة؛
مع تحقق مختلف409. تعرض الاستجابة أحدث challenge دون recovery_token.

POST confirm body: operation_id وcode. يتحقق الخادم من OTP والغرض والهدف
وملكية الحساب وأهلية الرحلات وتوفر الرقم ذريًا مع التعديل. لا استهلاك جزئي
لرمز مع نجاح تعديل غير مسجل؛ لا محاولة جديدة بمعرف مختلف بعد timeout.
200 data: operation_id وchallenge_id وpurpose وstatus=completed وcompleted_at.
يعاد نفس المورد لإعادة نفس العملية، دون تعديل جديد أو وقت جديد.
نفس العملية ببيانات مختلفة409 IDEMPOTENCY_CONFLICT. تُقارن حمولة التأكيد
المطبعة بما فيها الرمز لإعادة عملية مكتملة، ولا تعاد محاولة OTP مستهلكة
كمورد مستقل. عدم تطابق الغرض/التحقق/الهدف لا يغير حسابًا آخر.

نجاح الحذف يعطل الوصول للحساب ويبطل جلساته؛ نجاح تغيير الرقم يحدث حسابه
نفسه ويبطل جلساته أيضًا، ثم يعود المستخدم للدخول بالرقم الجديد. لا يصدر
هذا endpoint access_token أوrefresh_token. تفاصيل الاحتفاظ والحذف لدى
المنظومة وتدقيق الموظفين خارج قرار العميل؛ لا نعد بزمن مسح قانوني مختلق.

يحفظ الخادم سجل نتيجة وgrant استعادة محدودًا24 ساعة على الأقل مع
idempotency، حتى بعد إبطال جلسة الحساب. GET operation يحتاج token مطابقًا
لنفس العملية؛ لا يكشف رقمًا أو ملف مستخدم.200 data:null تعني لم تنفذ
هذه العملية بعد، و200 مع receipt تعني مكتملة. token مجهول/منتهي/لعملية
أخرى401 RECOVERY_INVALID دون كشف الوجود. لا تنفذ GET أثرًا ولا تعيد حسابًا
محذوفًا. لا تعمم استثناء جلسة ملغاة إلى بقية المسارات.

عند فقد رد start يعاد نفس operation_id والغرض والهدف ويعود نفس التحقق
وgrant؛ لا يرسل رمز جديد. عند فقد confirm يجمد العميل الرمز والنية،
ويقرأ receipt أو يعيد نفس confirm. لا يوجد outbox دائم في هذا الإصدار؛
المسودة والـgrant غير المقبولين لعمر الصفحة. بعد إعادة تشغيل التطبيق
تحدد استعادة Auth وضع الحساب من الخادم، ولا يختلق العميل نجاح عملية مفقودة.

## الأخطاء

401 UNAUTHENTICATED أوRECOVERY_INVALID؛403 FORBIDDEN/ACCOUNT_REQUIRED؛
404 CHALLENGE_NOT_FOUND؛409 ACTIVE_TRIP_EXISTS/PHONE_UNCHANGED/PHONE_IN_USE/
IDEMPOTENCY_CONFLICT؛410 OTP_EXPIRED؛422 VALIDATION_ERROR/OTP_INVALID؛
429 OTP_COOLDOWN/OTP_ATTEMPTS_EXCEEDED/RATE_LIMITED؛503 SERVICE_UNAVAILABLE.
الرفض المعروف قبل الأثر يتيح التصحيح. timeout وإخفاق النقل أو استجابة
غير مطابقة قد تعني أثرًا غير محسوم، فتظل نفس النية مقفلة حتى الحسم.
لا تعرض تفاصيل الحساب الآخر عند PHONE_IN_USE. لا fallback إلىmock.

## المحاكاة والاختبارات

ACCOUNT_MANAGEMENT_DATA_MODE يرث DATA_MODE؛ ACCOUNT_MOCK_SCENARIO:
success|offline|lost_response|phone_in_use. كود fixture الأول123456 وبعد
أول resend654321، للاختبار المحلي فقط ولا يظهر في UI كسر نجاح خادمي.
التطبيق ينهي جلسة المحاكاة ويمسح بياناتها عند القبول؛ هذا ليس حذف حساب
حقيقيًا. اختبارات العقد تطابق أمثلة التحقق والنتيجة بالمستودع والـmapper.
لا SMS حقيقي أو اختبار خادم أو استيراد Postman فعلي ضمن الأدلة الحالية.
