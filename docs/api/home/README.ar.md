# تسليم Home إلى فريق الباكند — تم

**الحالة: مقترح v1، غير منفّذ على خادم حقيقي.** يعمل تطبيق Flutter حاليًا بـ Mock معزول؛ تغيير `HOME_DATA_MODE=api` يُظهر `SERVICE_UNAVAILABLE` بوضوح حتى تتوافر واجهة حقيقية ومحوّل Repository. لا يُرسل طلب HTTP فعلي حاليًا.

## المطلوب من Laravel

إنشاء **GET /api/v1/home** عام للقراءة فقط، لإرجاع بطاقات الصفحة والخدمات المتوفرة؛ ليس مصدرًا لهوية المستخدم أو موقعه أو طلباته أو عداد إشعاراته. يعيد غلاف نجاح `data`، وغلاف خطأ `error.code` و`error.message.ar/en` المطابق لاتفاق Auth. لا يحتاج تسجيل دخول أو Bearer token ولا تُرسل بيانات الهاتف المحلية. يجب أن يرد بنفس الحمولة ثنائية اللغة بالعربية والإنجليزية.

الحقول المطلوبة والقيود والأنواع وnullable وحالات HTTP في **home-v1.md**. لا توجد تعديلات POST/PATCH/DELETE ولا ترقيم للقائمة: مصفوفات صغيرة داخل لقطة واحدة. الترتيب في المصفوفات من الخادم، و`revision` يتغير عند تحديث المحتوى أو توفر الخدمة. في هذه الدفعة `ride` فقط متاح؛ `food` و`shopping` يعرضان «قريبًا» دون تنفيذ.

## الربط مع واجهة Flutter

1. تحية/رقم هاتف: الحالة الموجودة محليًا في Auth (لا endpoint جديد).
2. البطاقات والعناوين الترويجية والخدمات: `HomeRepository.load` ← `GET /home`.
3. بدء طلب الرحلة: تنقل محلي إلى `CustomerNavigation.openRideRequest`، ثم يملك فريق Ride التسعير والحجز.
4. «طلباتي» و«الإعدادات» و«الإشعارات»: تنقل محلي مستقل، ولا تعاد بياناتها داخل `GET /home`.

## Postman

استورد `home-v1.postman_collection.json` (Collection v2.1)، واضبط المتغير `base_url` على أساس API الذي ينتهي بـ `/api/v1`. الافتراضي `api.example.invalid` مقصود لمنع استدعاء خادم وهمي باعتباره منتجًا حقيقيًا. الطلب GET بلا توكن؛ عدّل `Accept-Language` إلى `en` لاختبار اللغة. توجد Saved Responses: نجاح عادي، نجاح فارغ، 503، 429. قارن JSON المرجعي ضمن `examples/` وfixture Flutter. الاستيراد والتشغيل ضد خادم حقيقي لم يتما لعدم وجود API منشور.

## معايير قبول الباكند

يرجع الخادم 200 حتى مع المصفوفات الفارغة، ويتحقق من التفرد، وعدم وجود مسار URL حر أو خدمات مفعلة غير معتمدة. الأخطاء دائمًا ذات كود ثابت ورسائل ar/en. طلبان متكرران GET لا يغيران بيانات أو يحجزان رحلة؛ احترم `Cache-Control` إن فُعل. قبل اعتماد الربط نحتاج مراجعة مشتركة للعقد واختبارًا حيًا للتعامل مع timeout/503/429.
