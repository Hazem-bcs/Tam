# TAM | تم — عقد العناوين المحفوظة v1.0

**الحالة:** مقترح مطلوب من مطور Laravel؛ غير منفذ أو مختبر على خادم حي.
مرجع Flutter: `features/addresses`. عنوان الأساس المتغير يشمل `/api/v1`.
الأمثلة اصطناعية، وبحث الأماكن يعيد استخدام عقد `ride_request` القائم.

## الترويسات والملكية

- `Accept: application/json` و`Accept-Language: ar|en`.
- `Authorization: Bearer <access_token>` إلزامي لكل عملية على /addresses، بما فيها القراءة. بحث /places عام وفق عقده القائم.
- `Content-Type: application/json` عند POST وPATCH.
- الضيف و`localAccess` والدخول المؤقت دون OTP لا ينتجون مصادقة صالحة للخادم.
- العناوين تخص الحساب الموثق؛ لا تقبل `user_id` من العميل. GET وPATCH
  لمعرف غير مملوك يعيدان404 دون كشف وجوده. DELETE لمعرف غائب أو غير مملوك
  يعيد204 بعد نجاح المصادقة، دون كشف وجود المورد لحساب آخر.

## النموذج والقيود

جميع الحقول التالية مطلوبة وغير قابلة لـnull في استجابة العنوان:

| الحقل | النوع | القيد |
|---|---|---|
| `id` | opaque string | ثابت وغير فارغ؛ يُرمَّز عند بناء URL |
| `name` | string | بعد trim: من1 إلى50 Unicode code points؛ الأسماء المكررة مسموحة |
| `icon` | string | `home / work / study / gym / other` |
| `location` | object | يحتوي الحقول الثلاثة التالية |
| `location.label` | string | بعد trim: من1 إلى200 code points؛ نص عادي دون HTML |
| `location.latitude` | number | finite ضمن-90..90 |
| `location.longitude` | number | finite ضمن-180..180؛ إحداثيات WGS84 |
| `created_at` | string | ISO-8601 UTC ينتهي بـZ، يولده الخادم |
| `updated_at` | string | UTC Z و>=created_at؛ لا يتغير عند تكرار تعديل مطابق |

في الإنشاء والتعديل يرسل العميل `name` و`icon` و`location` فقط.
يرجع الخادم الاسم والعنوان بعد إزالة المسافات الطرفية. اختيار الموقع
يأتي من بحث الأماكن الحالي؛ لا حاجة إلى endpoint جديد لتسمية الأيقونة
أو عرض خريطة. الحجز يحتفظ بنسخة من بيانات الموقع، لذلك تعديل عنوان محفوظ
أو حذفه لا يغير الرحلات السابقة ولا أجرتها.

## العمليات

### GET /addresses

استجابة200: `{"data":[Address...]}`. القائمة كاملة، مرتبة حسب
`created_at DESC, id ASC`، و`data=[]` نجاح عند الفراغ.
الحد الأقصى50 عنوانًا للحساب. هذا استثناء مقصود من pagination القوائم
العامة لمورد صغير محدود؛ لا `cursor` أو `meta` فيv1.

### GET /addresses/{id}

استجابة200: `{"data":Address}`. المعرف غير الموجود يعيد
`404 ADDRESS_NOT_FOUND`. راجع `examples/address-detail.json`.

### POST /addresses

الجسم: `{"name":...,"icon":...,"location":...}`.
استجابة201: `{"data":Address}` مع معرف وأوقات من الخادم.

`Idempotency-Key` مطلوب، غير فارغ، بطول لا يتجاوز128 محرفًا.
يخزن الخادم المفتاح مع الحساب والطريقة والمسار والجسم المنظّم لمدة24 ساعة
على الأقل. تكرار الطلب المطابق يعيد المورد بالمعرف نفسه، واختلاف الجسم
مع المفتاح نفسه يعيد `409 IDEMPOTENCY_CONFLICT`.

عند فقد الرد يحتفظ Flutter بالمفتاح والمدخلات ويعيد العملية نفسها؛ لا ينشئ
مفتاحًا جديدًا لكل محاولة ولا يعلن نجاحًا لم يتأكد منه. بلوغ50 عنوانًا يعيد
`409 ADDRESS_LIMIT_REACHED`. يفحص الخادم تكرار المفتاح قبل الحد العددي
حتى يمكن إعادة محاولة إنشاء العنوان الخمسين بنجاح.

إذا حُذف المورد بعد إنشائه ثم تكرر POST بمفتاحه ضمن مدة الاحتفاظ، يعيد
`404 ADDRESS_NOT_FOUND` ولا ينشئ نسخة جديدة. إذا عُدِّل المورد لاحقًا، يرجع
المورد الحالي بالمعرف نفسه؛ تظل مقارنة الجسم مع جسم الإنشاء الأصلي.

### PATCH /addresses/{id}

الحقول القابلة للتعديل `name/icon/location` مطلوبة كلها؛ المقصود استبدال
هذه المجموعة كاملة، وليس merge جزئيًا فيv1. استجابة200: `{"data":Address}`.
يبقى `id/created_at` ثابتين. التعديل المطابق idempotent ولا يغير
`updated_at`. عند كتابات مستقلة متزامنة يفوز آخر حفظ ناجح؛ لا يوجد
optimistic version فيv1. المعرف الغائب يعيد404.

### DELETE /addresses/{id}

استجابة204 دون body؛ التكرار يعيد204 أيضًا. يتأثر دفتر العناوين فقط.
لا تُحذف رحلة سابقة ولا تتغير نسخة الموقع المحفوظة داخل حجز.

### GET /places — إعادة استخدام

يستخدم اختيار الموقع [عقد بحث الأماكن الحالي](../ride_request/ride_request-v1.md).
Collection تحتوي مثالًا منه لتسهيل الفهم؛ العقد الأصلي هو مرجع query وشكل
النتائج. لا قاعدة أماكن أو endpoint منافس داخل ميزة العناوين.
اختيار عنوان محفوظ لا يمنح صلاحية حجز API؛ تطبق سياسة الحجز بصورة مستقلة.

## الأخطاء وإعادة المحاولة

الشكل الموحد: `{"error":{"code":"STABLE_CODE","message":{"ar":"...","en":"..."}}}`.
تتخذ Flutter القرار بواسطة code؛ النص المعروض قابل للترجمة.

| HTTP | code | الحالة |
|---|---|---|
|401|`UNAUTHENTICATED`|جلسة غائبة أو غير صالحة|
|403|`FORBIDDEN`|العملية ممنوعة|
|404|`ADDRESS_NOT_FOUND`|المورد غير متاح للحساب|
|409|`ADDRESS_LIMIT_REACHED`|بلوغ الحد50|
|409|`IDEMPOTENCY_CONFLICT`|المفتاح مرتبط بجسم مختلف|
|422|`VALIDATION_ERROR`|حقول أو إحداثيات غير صالحة|
|429|`RATE_LIMITED`|احترام Retry-After إن وجد|
|503|`SERVICE_UNAVAILABLE`|الخدمة غير متاحة|
|500|`INTERNAL_ERROR`|عطل عام دون عرض تفاصيل داخلية|

خطأ النقل أو timeout لا يثبت أن التعديل لم يُطبَّق. الإنشاء يعاد بالمفتاح
والجسم نفسيهما، والتعديل بالجسم نفسه، والحذف آمن للتكرار؛ ثم تزامن القائمة.
بعد فشل refresh تُحفظ آخر قراءة موثوقة وتظهر رسالة خطأ واضحة. لا تعرض
قائمة قديمة على أنها نجاح تحديث جديد.

## التدفقات ومسؤوليات التنفيذ

| فعل المستخدم | Domain contract | عملية الخادم |
|---|---|---|
|فتح القائمة/التحديث|`AddressesRepository.list`|GET /addresses|
|فتح التعديل|`get`|GET /addresses/{id}|
|حفظ مكان|`create`|POST /addresses|
|تعديل مكان|`update`|PATCH /addresses/{id}|
|حذف مكان|`delete`|DELETE /addresses/{id}|
|البحث عن الموقع|`AddressPlaceSearch.search`|GET /places القائم|
|اختيار عنوان للحجز|`TripLocation` snapshot|لا endpoint إضافي؛ يعاد التسعير عبر الحجز|

الباكند مسؤول عن المصادقة والملكية والتحقق والحد العددي والترتيب
وidempotency. Flutter مسؤول عن الواجهة والحالات والـmapping والتنقل
والتحقق المحلي، مع بقاء التحقق النهائي على الخادم.

المحاكاة الحالية مصدر واحد في ذاكرة الجلسة. عند الخروج تُمسح تعديلات
الحساب وتعود fixtures الاصطناعية فقط. هذه سياسة تطوير؛ ليست سياسة حذف
العناوين الحقيقية من الخادم. GPS والخريطة الحية والتخزين المحلي الدائم
خارج هذه النسخة. API repository غير الجاهز يفشل بوضوح ولا يسقط إلى mock.

النقاط المطلوب تثبيتها مع الباكند: قبول الحد50، مدة الاحتفاظ بالمفاتيح
والاستجابة بعد حذف المورد، واعتماد آخر كتابة ناجحة دون versioning.
