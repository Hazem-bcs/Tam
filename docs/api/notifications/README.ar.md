# حزمة إشعارات العميل — Tam | تم

**العقد المقترح:** `notifications-v1`، إصدار 1.0، حالة **مقترح للباكند — غير منفّذ أو متحقق حيًا**.

هذه الحزمة لتنفيذ واجهة Laravel عند جاهزية الباكند. تطبيق Flutter ينفذ حاليًا صندوق إشعارات **بمحاكاة ذاكرة محلية فقط**. لا يوجد إرسال Push أو FCM أو تسجيل أجهزة أو طلب صلاحيات إشعارات، ولا تُستخدم جلسات الدخول المؤقت كجلسات API.

## الملفات
- [notifications-v1.md](notifications-v1.md): تفاصيل الحقول والواجهات والأخطاء والتزامن.
- [notifications-v1.postman_collection.json](notifications-v1.postman_collection.json): مجموعة Postman v2.1 بأمثلة استجابة محفوظة.
- [examples](examples/): أمثلة JSON اصطناعية تطابق بيانات المحاكاة ومفسّر Dart.

## ما الذي يحتاجه الباكند؟
1. **عرض الصندوق:** `GET /notifications?limit=20&cursor=...`، مرتب نزولًا بتاريخ الإنشاء ثم المعرّف.
2. **العداد الموحّد:** `GET /notifications/unread-count`، عدد غير المقروء **لكل الحساب**، وليس الصفحة المعروضة فقط.
3. **تعليم واحد:** `POST /notifications/{id}/read`، يُعيد عنصر الإشعار بحالة القراءة المعتمدة.
4. **تعليم الكل:** `POST /notifications/read-all`، يُعيد وقت العملية وعدد غير المقروء المتبقي.

تلك العمليات تتطلب `Authorization: Bearer <access_token>` في وضع API الفعلي؛ لا يُسمح باستبداله باتصال ضيف. عند الفشل تبقى البيانات القديمة المعروفة معلّمة على أنها لم تُحدّث، ويُتاح إعادة المحاولة.

## إعداد Postman
استورد Collection JSON كملف Postman Collection v2.1، واضبط `base_url` (مثال توثيقي `https://api.example.com/api/v1`) و`access_token` الخاص ببيئة اختبار مصرّح بها و`language` (`ar` أو `en`). المتغيرات `notification_id`, `limit`, `cursor` اصطناعية؛ لا توجد أسرار في الحزمة. ابدأ بطلب الصفحة الأولى، ثم استعمل `meta.next_cursor` للصفحة التالية، ثم العداد، والتعديل الفردي/الجماعي.

**حدود التحقق:** JSON والعينات تفحص محليًا، واختبارات Flutter تفحص القراءة والترقيم والمخاطر. لم يُستدعَ خادم، ولم يُجرَ استيراد يدوي فعلي إلى واجهة Postman؛ صلاحية JSON وحدها ليست برهانًا على تنفيذ endpoints.

## الربط المستقبلي
مصدر العداد ضمن Domain هو `NotificationsUnreadCountSource` (دالتا `getUnreadCount()` و`unreadChanges`). لا يصنع Home عدادًا ثانيًا؛ يحتاج المشرف تسجيل مصدر الميزة ضمن دورة حياة `TamApp` وتركيبه في Home أثناء التكامل. النسخة الحالية تستعمل مستودع mock واحدًا على مستوى نقطة دخول الإشعارات؛ استبداله بمصدر API الحقيقي يستلزم مصادقة صحيحة واختبارات نقل قبل تفعيل `NOTIFICATIONS_DATA_MODE=api`.
