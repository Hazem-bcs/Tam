# TAM | تم — عقد الرحلة الجارية v1

الحالة: **مقترح لمطور Laravel، غير منفذ أو متحقق حيًا**. التاريخ:2026-11-09.
يمد [الحجز](../ride_request/ride_request-v1.md) و[طلباتي](../trips/trips-v1.md)
و[الجدولة](../scheduling/scheduling-v1.md) صراحة؛ لا مورد رحلة أو إلغاء موازٍ.
المحاكاة الحالية محلية ولا تصدر جلسة Auth أو طلب سائق حقيقيًا.

## التدفق وصلاحية الأطراف

بعد تأكيد الحجز يفتح العميل /active-trip/{id} بالمعرف فقط، ويقرأ المورد
الأحدث؛ لا يعتمد على نسخة في route.extra. يستطيع استعادة رحلته من الرئيسية
أو فتح المتابعة من تفاصيل طلباتي. الأوامر التي تخص السائق/الخادم لا ينفذها
عميل الراكب: تعيين سائق، وصوله، بدء الرحلة، إنهاؤها أو إرسال موقع السيارة.
لم يضف Flutter أزرارًا تمنح هذه الصلاحيات؛ المحاكاة تنفذها في طبقة Data.

| الحالة | المعنى | انتقالات الخادم المسموحة | إلغاء العميل |
|---|---|---|---|
| scheduled | موعد محفوظ | requested عند الموعد | نعم |
| requested | البحث عن سائق | confirmed أو no_driver | نعم |
| confirmed | قبول/تعيين سائق | driver_en_route | نعم |
| driver_en_route | السائق في الطريق للانطلاق | driver_arrived | نعم |
| driver_arrived | وصل وينتظر الراكب | in_progress | نعم |
| in_progress | الرحلة بدأت | completed | لا |
| completed | وصلت الوجهة | نهائية | لا |
| cancelled | ألغيت | نهائية | تكرار آمن فقط |
| no_driver | لم يتوفر سائق | نهائية | لا |

الإلغاء يحوّل الحالات المسموحة إلى cancelled ذريًا. لا رسوم أو خصم
مخترع في هذا الإصدار. no_driver لا يعيد تسعير الطلب القديم أو إعادة تشغيله؛
«طلب رحلة جديدة» ينقل الموقعين فقط إلى عرض سعر ومعرف جديدين. إعادة الطلب
فورية أيضًا عند انتهاء/إلغاء رحلة مجدولة. التقييم والمحادثة والاتصال
والإشعارات لها عقود مستقلة؛ راجع chat/completion/driver_contact/notifications.
تغيير الموعد بعد الحجز خارج النطاق؛ يعاد طلب بسعر وموعد جديدين بعد الإلغاء
المسموح بدل تعديل رحلة مؤكدة ضمنيًا.

## القواعد العامة

base_url متغير يشمل /api/v1. كل العمليات أدناه تتطلب
`Authorization: Bearer {{access_token}}` و`Accept: application/json`؛
Accept-Language:ar|en اختياري. guest/localAccess ليسا جلسة API.
النجاح data والفشل error.code وerror.message.ar/en وفق Auth.
المعرفات opaque strings غير فارغة، وترمّز كمكوّن URL عند الاستعمال.
كل التواريخ ISO-8601 UTC Z بتقويم صحيح، وأجزاء ثانية اختيارية حتى6 منازل.
وقت الجدولة ونطاق30 دقيقة..7 أيام وUTC+03:00 للعرض كما في عقد الجدولة.

## Trip الموسع — نفس المورد في الحجز وطلباتي والمتابعة

تبقى حقول Trip المطلوبة: id، pickup، destination، vehicle_class_id، fare،
status، created_at، وscheduled_at للمجدولة (nullable/اختياري للفورية القديمة).
Location={label:نص1..200،latitude/longitude:finite ضمن الحدود الجغرافية}،
وMoney={amount_minor:int>=0،currency:3 أحرف كبيرة،minor_unit:int0..3}؛ لا floats للمال.
أضيفت driver_en_route وdriver_arrived وno_driver إلى enum status،
وactive يشمل scheduled/requested/confirmed/driver_en_route/driver_arrived/in_progress.
no_driver تظهر في all فقط، دون اختراع فلتر خامس؛ ترتيب created_at DESC ثم id ASC باقٍ.

الحقل **live:object** مطلوب في استجابات هذه الحزمة، ومسموح كامتداد اختياري
في عمليات Trip السابقة. سجلات W1 القديمة تظل قابلة للقراءة دون live أو مع null.
لكل رحلة تُتابع عبر هذه الحزمة يضمن الخادم نسخة live حتى للسجل التاريخي.

| live field | النوع والقيود |
|---|---|
| revision | int>=1، متزايد لكل تغيير حالة/بيانات، خاص بالرحلة نفسها |
| updated_at | UTC Z، آخر تغيير للحالة/البيانات، لا يعود للخلف |
| status_changed_at | UTC Z، بدء الحالة الحالية؛ created_at<=القيمة<=updated_at |
| driver | object|null، الحقل مطلوب nullable |
| position | object|null، الحقل مطلوب nullable |
| eta_seconds | int>=0|null، الحقل مطلوب nullable، تقدير لا ضمان |

driver غير null إلزامي لـconfirmed/driver_en_route/driver_arrived/in_progress.
لا driver/position/ETA في scheduled/requested/no_driver. يمكن حفظ بيانات
السائق للرحلة completed/cancelled، لكن **position وETA يجب أن يكونا null
لكل حالة نهائية**. لا ينشئ العميل سائقًا عند غياب الحقل.

driver: جميع الحقول مطلوبة غير nullable: id، name (عربي)، name_en، vehicle
(وصف المركبة/اللون)، vehicle_en، plate (معرف لوحة للعرض)، rating:number finite0..5.

اقتراح تكاملي اختياري للواجهة: `vehicle_image_url` رابط HTTP(S) لصورة المركبة أو null؛ عند غيابه أو تعذّر تحميله تظهر أيقونة المركبة. الحقل مقترح يحتاج اتفاق الباك إند وليس تأكيدًا لتوفره حاليًا.
لا صور وهمية أو أرقام هاتف شخصية أو روابط مكالمات/دردشة في هذا الإصدار.
position:latitude/longitude finite ضمن[-90,90]/[-180,180]، وrecorded_at UTC Z
<=updated_at، ولا position دون driver. إحداثيات الأمثلة اصطناعية وليست GPS.

السجل **ذري**: status وكل live تخص revision واحدًا. لا ترسل حالة من إصدار
وموقعًا من آخر. تغيير position.recorded_at أو ETA أو السائق يرفع revision.
نفس revision يعيد نفس المحتوى؛ رفض العميل الإصدار الأقدم لا يثبت انقطاع
الشبكة لكنه يمنع الرجوع إلى حالة قديمة. read-to-read قد يقفز عدة حالات
إذا لم يفتح العميل الشاشة؛ الخادم مصدر الحقيقة وليس عدد مؤقتات الهاتف.

## GET /trips/current

لا body أو query.200 مع data:Trip|null. null يعني لا توجد رحلة نشطة متاحة
للحساب، وليس فشل شبكة. يقرأ الخادم من موارد المستخدم نفسه في معاملة متسقة.
يُرجع الرحلة الفورية أو التي بدأ توزيعها فقط، بالأحدث created_at ثم id ASC؛
لا تُرجع scheduled المستقبلية ولا الرحلات النهائية. إذا كانت كل الرحلات
مجدولة يعيد data: null؛ هذا فراغ حقيقي ولا يعني حذف الحجز أو فشل الاتصال.
تُعرض الحجوزات المجدولة خارج السجل في الرئيسية بواسطة
GET /trips?filter=scheduled&sort=scheduled_at_asc ضمن امتداد الجدولة، وتبقى
GET /trips/{id} وسيلة متابعة كل معرف مستقل. هذا تعديل مقترح بتاريخ
2026-11-18؛ يحتاج اعتماد الباكند قبل تفعيل API، ولا يغير حدود Auth.
يجب تعريف هذا المسار قبل /trips/{id} في Laravel لمنع تفسير current كمعرف.
الأمثلة live-en-route وcurrent-empty في examples/ لهذه العملية؛ live-scheduled للتفاصيل بالمعرف.

## GET /trips/{id}/live

id مطلوب وopaque.200 مع data:Trip الموسع. يعيد أحدث snapshot للحساب فقط،
ويستمر في إعادة المورد بعد الإلغاء/الانتهاء ليحسم العميل النتيجة. غير موجود
أو غير مملوك:404 TRIP_NOT_FOUND، دون كشف سائق أو موقع حساب آخر.
لا نجاح data:null لهذا endpoint؛ يحول Data adapter404 إلى غياب مورد محليًا.
GET في الباكند لا يطلب سائقًا ولا يبدأ/ينهي الرحلة؛ محرك المحاكاة فقط
يستدرك الزمن محليًا قبل القراءة لأنه يمثل أحداث السائق غير الموجودة بعد.

polling مقترح كل5 ثوانٍ أثناء المتابعة، وعند الاستئناف/إعادة الاتصال.
لا يشترط WebSocket أو endpoint أحداث جديد. واجهة Repository تتيح
invalidation اختياريًا؛ لا يغني وصول حدث عن قراءة snapshot ذري.
بعد تثبيت معرف current يتابع العميل هذا المعرف حتى النهاية، ثم يعود إلى
current فقط عند فتح استعادة جديدة. لا ينتقل تلقائيًا إلى رحلة شخص/معرف آخر.

## POST /trips/{id}/cancel — نفس عملية طلباتي

بلا body؛ لا API إلغاء بديل.200 مع نفس Trip بحالة cancelled وlive.updated_at
وrevision محدثين. يحتفظ بالموقعين والسعر والموعد والسائق إن وجد، ويمسح
position وETA. تكرار الإلغاء يعيد المورد الملغى نفسه دون أثر أو رسوم إضافية.
in_progress/completed/no_driver:409 TRIP_NOT_CANCELLABLE؛ غير الموجود/المملوك404.
يتحقق الخادم من الحالة والملكية ويحدثها ذريًا، حتى لو ظهر زر الإلغاء لحظة
قبل بدء الرحلة. لا يعتمد على أزرار العميل كإذن أو منع.

timeout/503/رد معطوب بعد الإرسال نتيجة غير محسومة: لا يختلق العميل نجاحًا،
ويمنع طلب بديل من شاشة المتابعة، ويعيد **نفس عملية الإلغاء لنفس المعرف**.
العملية idempotent ولا تحتاج مفتاح إنشاء جديد. القراءة التي تعيد cancelled
تحسم النجاح، والحالة غير القابلة للإلغاء تحسم تعارض الحالة؛ القراءة التي
ما زالت قابلة للإلغاء لا تثبت وحدها أن أثرًا متأخرًا لن يحدث، فيبقى retry متاحًا.
لا ترجع200 مع requested كأن الإلغاء نجح.409/404/401/403 رفض صريح يعيد قراءة الحالة.

## الاتصال والبيانات القديمة

آخر snapshot يبقى ظاهرًا عند فشل التحديث مع تنبيه أنه قد تغير. تتوقف
أفعال الإلغاء الأولى عند انقطاع القراءة، مع إبقاء retry الآمن لإلغاء غير محسوم.
يتحقق العميل من هوية الرحلة وrevision؛ الرد المتأخر لا يمحو إلغاءً أحدث.
القراءة الناجحة تحدث وقت المزامنة المحلي حتى إذا لم تتغير revision،
فـupdated_at ليس heartbeat للاتصال. بعد15 ثانية بلا مزامنة تظهر الحالة قديمة.
position أقدم من30 ثانية تُعرض كآخر موقع معروف مع تنبيه، وتُخفى ETA؛
لا تخلط حداثة اتصال HTTP بحداثة GPS. عند الانقطاع تُخفى ETA أيضًا.

الساعة والمدد قابلة للحقن للاختبار. الخادم هو مرجع تسلسل/وقت الحالات،
وسياسة فروق الساعة وRetry-After عند429 تضبط مع طبقة النقل عند الربط؛
لا HTTP adapter أو تحكم بخدمة حية في هذا التسليم.

## الأخطاء

401 UNAUTHENTICATED،403 FORBIDDEN،404 TRIP_NOT_FOUND للمعرف غير المرئي،
409 TRIP_NOT_CANCELLABLE للإلغاء،422 VALIDATION_ERROR للمدخلات،
429 RATE_LIMITED،503 SERVICE_UNAVAILABLE،500 INTERNAL_ERROR. JSON المعطوب400
إن أرسل جسمًا غير مطلوب. error.message.ar/en نصان للشرح؛ القواعد من error.code.
NETWORK_ERROR/INVALID_RESPONSE/STALE_DATA أكواد عميل محلية، لا HTTP وهمي لها.
الأمثلة والسaved responses تغطي النجاح والفراغ والأخطاء الثنائية اللغة.

## المحاكاة والتحقق

ACTIVE_TRIP_DATA_MODE يرث DATA_MODE؛ api غير الجاهز يفشل ولا يعود إلى mock.
ACTIVE_TRIP_MOCK_SCENARIO=success|no_driver|disconnect إعداد مركزي.
النجاح الافتراضي: بحث12ث، قبول5ث، وصول25ث، انتظار15ث، رحلة30ث؛ هذه مدد
عرض محاكاة مُسرعة وليست أوقات خدمة حقيقية. disconnect يقطع قراءة المتابعة
بين20 و35ث من الإنشاء، مع استمرار بيانات السائق في المصدر. لا UI mode switch.

MockTripStore مصدر الحالة الوحيد؛ تحديث live والحالة بإصدار متوقع ذري.
المحرك مملوك للتطبيق ويتابع عند مغادرة الصفحة، ويستدرك عند العودة،
ويبدأ scheduled عند الموعد طالما العملية تعمل. إغلاق التطبيق ينهي الذاكرة؛
لا وعد بتشغيل خلفي أو إشعارات أو حفظ دائم. الخروج يعزل الجلسة ويرجع seed الاصطناعي فقط.
حزم JSON مولدة من المحاكاة الفعلية بساعة2026-11-09T12:00Z وIDs اصطناعية؛
الاختبارات تعيد نفس التسلسل وتقارنها بالـcodec وPostman. صلاحية JSON أو
فحص بنية Collection ليس استيراد واجهة Postman أو طلب HTTP ناجحًا.
الخرائط الحية والصور والصقل النهائي مرحلة ثانية؛ تقييم/محادثة/اتصال لاحقًا.
