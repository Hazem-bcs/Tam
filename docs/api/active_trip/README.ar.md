# الرحلة الجارية — إلى مطور الباكند

اقرأ [العقد العربي](active_trip-v1.md)، ثم استورد
`active_trip-v1.postman_collection.json` بصيغة v2.1. الحزمة مقترحة وليست
خادمًا متصلًا. تضيف حالات وlive إلى مورد Trip نفسه، ولا تنشئ حجزًا موازيًا.

1. اضبط base_url شاملاً /api/v1، وaccess_token حقيقيًا وفق Auth.
2. ابدأ GET /trips/current لاستعادة رحلة الحساب؛ data:null فراغ صحيح.
3. ضع id الراجع في trip_id، واقرأ /trips/{id}/live دوريًا لآخر snapshot.
4. الحالة والموقع والسائق وETA يجب أن تخص revision واحدة متزايدة.
5. راجع Saved responses لجميع مراحل الرحلة والجدولة وعدم توفر سائق.
6. الإلغاء هو POST /trips/{id}/cancel نفسه من طلباتي؛ كرره بأمان بعد
   فقد الرد للمعرف نفسه، دون إنشاء رحلة أو خصم مال آخر.

عرّف current قبل المسار الديناميكي في Laravel. كل القراءة/الإلغاء مقيدة
بهوية الحساب؛ الضيف والدخول المحلي في Flutter ليسا توكن API.
المطابقة والوصول/البدء/الإنهاء أوامر للخادم/السائق، ولا تمنحها للراكب.
لا دعوة لمستخدم أو اتصال أو رسائل فعلية ضمن الحزمة. أمثلتها اصطناعية.
راجع العقد لحدود الاتصال وموقع GPS القديم، وملف التسليم لأدلة التحقق.

## متابعة واجهة ahmad-ui — 2026-11-18
تأكيد الحجز لا يفتح خريطة جديدة: يبقى المشهد نفسه وتتحول اللوحة السفلية حسب live.status.
كل دخول لمشوار يبدأ بالتحقق من current؛ فشل التحقق يُظهر إعادة المحاولة ولا يسمح بطلب مكرر.
في Mock فقط تُحفظ snapshots محليًا في مساحة التطبيق وتُستعاد لنفس الهاتف المحلي/الضيف
بعد فتح التطبيق مجددًا والدخول وفق Auth الحالي. ليست جلسة backend أو طابور حجز offline.
تبديل المالك أو تسجيل الخروج يمسح snapshot؛ مسار API يظل مرجعه GET /trips/current
ولا يستخدم هذه المحاكاة fallback. الساعة التجريبية تلحق المراحل المنقضية عند الاستعادة.
