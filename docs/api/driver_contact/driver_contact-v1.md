# تم — الاتصال بالسائق، عقد v1

الحالة: مقترح للتنفيذ، لا خادم حي متصل. يقرأ العميل وسيلة اتصال للسائق
المعيّن لرحلته ثم يفتح تطبيق الهاتف. لا ينفذ عميل الراكب تعيين سائق،
ولا يدعي أن فتح تطبيق الهاتف يثبت إجراء مكالمة أو رد الطرف الآخر.

## الطلب والملكية

GET /trips/{trip_id}/contact?driver_id={expected_driver_id}
بالنسبة إلى base_url الذي يشمل /api/v1. يلزم Authorization:Bearer
وAccept:application/json. يتحقق الخادم من مالك الرحلة وحالتها والسائق
الحالي؛ driver_id شرط تطابق، وليس اختيار سائق أو إذن اتصال بأي شخص.
الضيف وlocalAccess ليسا جلسة API.

يسمح الاتصال فقط في confirmed/driver_en_route/driver_arrived/in_progress
مع سائق معيّن. scheduled/requested والحالات النهائية لا تسمح بالاتصال.
تغير السائق يعيد409 DRIVER_CHANGED دون رقم السائق السابق. غياب وسيلة
اتصال مخولة يعيد409 CONTACT_UNAVAILABLE. الرحلة الأجنبية403 أو404
TRIP_NOT_FOUND وفق سياسة إخفاء الوجود المتفق عليها. لا يكشف الرقم في
history أوالإشعارات أوlogs أو رسائل الخطأ.

## الاستجابة

200 envelope:

```json
{
  "data": {
    "trip_id": "mock-trip-1",
    "driver_id": "mock-driver-001",
    "phone_e164": "+963900000000",
    "expires_at": "2026-11-09T12:02:17.000Z"
  }
}
```

كل الحقول مطلوبة وغيرnull؛ id نص غير فارغ، وphone_e164 مطابق
`^\+[1-9]\d{7,14}$` بلاUSSD أورموز أوextensions أوURI. expires_at توقيتUTC Z
صحيح، بصلاحية لا تزيد على دقيقتين من إصدار الخادم. لا يُخزن الرقم دائمًا
أو يعرض قبل الحاجة. يختار الخادم رقمًا مخولًا لهذه الرحلة؛ يمكن أن يكون
وسيطًا إذا وفرت المنظومة ذلك. لا يفرض العقد مزود إخفاء أرقام أو تكلفة
اتصال أو وعد حماية رقم لم تُجهز بنيته.

## سلوك Flutter

يفحص العميل هوية الرحلة والسائق وصلاحية الرد، ثم يبني URI tel من الرقم
المتحقق منه فقط. لا يفتح URL حرًا من الخادم، ولا يطلب CALL_PHONE أو يبدأ
اتصالًا مباشرًا دون تطبيق الهاتف. محول المنصة يستخدم url_launcher؛ فشل
الجهاز أو غياب تطبيق الهاتف يعرض DIALER_UNAVAILABLE محليًا. القبول يعني
تسليم URI للنظام فقط، وليس مكالمة أو فاتورة أو تأكيد رد السائق.

إذا انتهت الجلسة أو أُغلقت الصفحة أو غُطيت بمسار آخر أو انتقل التطبيق للخلفية قبل رد الخدمة،
لا يفتح اتصالًا متأخرًا؛ يلزم ضغط جديد من المستخدم بعد العودة.
يتلقى المستودع إبطال أهلية الاتصال أو هوية السائق من مصدر Trip المشترك؛
التغيير المعروف قبل فتح التطبيق يلغي النتيجة الجارية ويحتاج ضغطًا جديدًا.
تحديث الموقع أو الانتقال بين حالات تسمح بالاتصال مع السائق نفسه لا يبطل الطلب.
يربط محول API المستقبلي المصدر نفسه مع تغييرات الرحلة والجلسة؛ لا يختلق العميل
معرفة بتغيير خادمي لم يصل إليه، ولا يضمن بقاء الرحلة نشطة بعد تسليم URI للنظام.
GET بلا أثر؛ لا Idempotency-Key ولا endpoint يدعي أن المكالمة تمت.

## الأخطاء والمصدر

401 UNAUTHENTICATED؛403 FORBIDDEN؛404 TRIP_NOT_FOUND؛409 DRIVER_CHANGED أو
CONTACT_UNAVAILABLE؛422 VALIDATION_ERROR؛429 RATE_LIMITED؛503 SERVICE_UNAVAILABLE.
البنية error.code وerror.message.ar/en، دون data في استجابة الفشل.

أرقام الأمثلة fixtures لا تُطلب فعليًا؛ mock يحقن MockPhoneDialer ويعرض
نتيجة محاكاة دون تمرير رقم إلى النظام. DRIVER_CONTACT_DATA_MODE يرث
DATA_MODE؛ السيناريو DRIVER_CONTACT_MOCK_SCENARIO=success|offline|unavailable.
المصدر MockTripStore نفسه، دون قائمة سائقين موازية. API غير المتصل يفشل
SERVICE_UNAVAILABLE دون fallback.

الاختبارات تشمل المنطق والـURI والهوية والخلفية والجلسة والأمثلة. فتح
تطبيق الهاتف على جهاز فعلي وربط الخادم واختبارهما يبقيان لمرحلة الربط.
