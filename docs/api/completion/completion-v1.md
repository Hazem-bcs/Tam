# عقد ملخص الرحلة والتقييم v1

الحالة: **مقترح للباكند، لا تكامل HTTP منفذ أو تحقق حي**. الإصدار1 داخل
`data.version`، والأساس المتغير `{{base_url}}` يشمل بادئةAPI مثل`/v1`.
يطبق الباكند جلسةBearer موثقة وملكية الرحلة في كل GET/POST. الضيف والدخول
المحلي في تطوير المحاكاة لا يكوّنان مستخدمًا موثقًا أو tokens.

## التدفق ومصدر البيانات

الرحلة نفسها منTrips وActiveTrip مصدر الملخص، ويشترطstatus=completed.
يدعم التاريخ القديم الذي لا يحويlive أوdriver؛ التقييم لتجربة الرحلة.
يعرض معرف الطلب وتاريخ إنشائه ومواقعه وحالته ومبلغbooking.fare المسجل،
والسائق اختياري إن وُجد فيlive. لا استنتاج لدفع أو إيصال/ضريبة/خصم أو
مسافة/مدة، ولا أسعار نهائية مختلقة. لا يغير العميل حالة الرحلة إلىcompleted.

| فعل الواجهة | Repository | HTTP |
|---|---|---|
| فتح/إعادة تحميل الملخص أو حسم الرد المفقود | fetch(tripId) | GET /trips/{trip_id}/completion |
| إرسال نجوم وتعليق | submitRating(tripId,stars,comment,idempotencyKey) | POST /trips/{trip_id}/rating |
| إعادة الإرسال بعد الفشل/فقد الرد | نفسsubmitRating بنفسintent | نفسPOST والمفتاح والحمولة |
| الرئيسية/رجوع/دعم الرحلة | callbacks محلية | لا endpoint مخترع؛ الدعم ميزة مستقلة |

## الطلبات

Headers مشتركة: `Authorization: Bearer {{access_token}}`, `Accept: application/json`.
POST يضيف`Content-Type: application/json` و`Idempotency-Key` غير فارغ.
معرفtrip_id نصopaque ثابت؛ يجبpath-encode عند إدخاله فيURL. لاpagination أوfilters.

POST body: `stars` عدد صحيح مطلوب1..5، `comment` نص مطلوب فيwire لكن اختياري
للمستخدم (الغياب في النموذج يرسل`""`). تُزال الفراغات الطرفية قبل الإرسال،
ويقبل الخادم النصcanonical نفسه فقط/يطبع قبل المقارنة حسب قاعدةtrim المشتركة.
الحد500 Unicode code points بعدtrim، وليسUTF-16 units ولاbytes ولاgraphemes؛
إيموجي منفرد خارجBMP يحسبcodepoint واحدًا. لاقطع صامت للنص. CompletionPolicy
المركزي يطبق الحد؛ تغيير المنتج يحتاج تحديث العقد والباكند والعميل معًا.

## النجاح200

كلGET وPOST يعيد`{"data": {...}}`، بالحقول التالية المطلوبة:

| الحقل | النوع والمعنى |
|---|---|
| version | integer=1 |
| revision | integer>=1؛ إصدار متزايد داخل ملخص الرحلة يزداد عند تغيّرtrip/rating |
| trip | TripWireCodec المشترك كاملًا، ولاحقًاlive اختياري وفقعقد ActiveTrip |
| rating | null أوكائنTripRating كامل |

حقولtrip: `id` نص، `status="completed"`، `created_at` timestampUTC بصيغةISO8601
معZ؛ `pickup/destination` كائناتlabel/latitude/longitude؛ `vehicle_class_id` نص؛
`fare` بقيم`amount_minor` integer>=0 و`currency`ISO4217 و`minor_unit`0..3.
القيمة25000/SYP/0 تعني25000ليرة. `scheduled_at` اختياريUTC إن كان الطلب مجدولًا؛
`live` اختياري، ولا يصنعه الملخص. أمثلةالرحلات القديمة بلاlive معتمدة ضمنالحزمة.

حقولrating المطلوبة: `id` نص ثابت، `trip_id` يطابقtrip.id، `stars` integer1..5،
`comment` نصtrimmed<=500codepoints ويمكنفارغًا، `idempotency_key` نصopaque مطابق
لطلب الإنشاء، `submitted_at`ISO8601UTC معZ ولايسبقtrip.created_at أووقت اكتماله
المسجل فيlive إن وجد. لايقعrevision مختلف لمحتوىمختلف عندنفسالإصدار؛ ولاينقص.

تردPOST الأولية والإعادةبنفسالحالة200 والموردنفسه؛ لاtimestamp أوid أوrevision
جديد للإعادة. GET بلا تقييم يعيدrating:null، وليس404 أو قائمة فارغة.
حقولidempotency تحفظ داخل حساب صاحبالتقييم ولا تُكشف لحسابآخر.

## عدم التكرار والتزامن

تقييم واحدimmutable لكلرحلة ولكلصاحبها، بفرضtransaction/unique constraint
علىtrip_id ومعرفالمالك. المفتاحعشوائيآمن مستقلعنالساعةوعمرCubit. يسجّل الخادم
المفتاحوالحمولةcanonical ونتيجتهاأتوميًا، بنطاقالحساب؛ لايعتمد العميلعلىتوقيت
الساعةلتوليدهوية. نفسالمفتاح/الرحلة/النجوم/النص يعيدنفسالمورد؛ المفتاحنفسه
لحمولةأورحلةمختلفة409IDEMPOTENCY_CONFLICT. مفتاحجديدلرحلةمقيّمة
409RATING_ALREADY_SUBMITTED. تُحفظالمفاتيح طوالعمرالمورد (أوlookupدائم مكافئ).
لا تعديل/حذف/تخطي مصطنع للتقييم. الرفض قبل القبول لا يحجزالمفتاح.

بعدtimeout/ردغيرمؤكد يحتفظالعميلبالنجوموالتعليقوالمفتاح دونتعديل؛ GET يحسم
التقييمالمحفوظ أوPOST يعيدنفسالطلب. لايدعي فشلًا مؤكدًا أويسجلنجاحًا محليًا.
يُتحقق منtrip/rating/intent فيالإقرار؛ readsالأقدم لا تمسحackأحدث، ولايقلب
ratingمحفوظ إلىnull. تغييرالجلسةيبطل الطلباتالجارية ويزيلصفحاتالبيانات.
الإقرارالمقبول بعدإغلاقالصفحة يبقىفيالخادم؛ إعادةالفتح تقرأGET. المسوداتغير
المقبولةلاتُحفظدائمًا فيالعميل؛ هذاقرارالمرحلةالحاليةوليستعهدتسليمفيالخلفية.

## الأخطاء

الشكل: `{"error":{"code":"...","message":{"ar":"...","en":"..."}}}`.
الرسائل للإنسان، والأكواد ثابتة. كلاالنصين مطلوبانغيرفارغين.

| HTTP | code | السبب/تصرفالعميل |
|---|---|---|
|401|UNAUTHENTICATED|جلسةمفقودة/منتهية؛ لاطلبAPI باسمguest/localAccess|
|403|FORBIDDEN|رحلةليستملكالحساب؛ لاكشفبياناتها|
|404|TRIP_NOT_FOUND|معرفغيرموجود بعدتفويضالطلب|
|409|TRIP_NOT_COMPLETED|قراءةأوتقييمقبلcompleted؛ لايغيرالعميلالحالة|
|409|RATING_ALREADY_SUBMITTED|مفتاحجديدلرحلةمقيّمة؛ GETللتقييمالقائم|
|409|IDEMPOTENCY_CONFLICT|المفتاحذاته معpayloadأورحلةمختلفة؛ لاتبدلمفتاحًالتجاوزه|
|422|VALIDATION_ERROR|نجوم/تعليق/مفتاحغيرصالح؛ قبلالقبول|
|429|RATE_LIMITED|حدطلبات؛ Retry-Afterبالثواني عندتوفره، لاإعادةتلقائيةمتسارعة|
|503|SERVICE_UNAVAILABLE|عدمجاهزيةالخدمة؛ لاfallbackمحاكاة|

NETWORK_ERROR وINVALID_RESPONSE وSESSION_ENDED أكوادعميلمحلية، ليستHTTP
responsesمختلقة. فقدtransportأثناءPOST غيرمؤكد، ويحتاجقراءة/إعادةبنفسالمفتاح.
الباكند مسؤولعنالتفويضوالحفظالأتوميوالإصدار؛ العميلمسؤولعنvalidationللتجربة
والعزلوحمايةالاستجاباتالمتأخرة، ولايغنيأيمنهماتحققعنالآخر.

## نقاط مفتوحة

العقد ينتظر مراجعةالباكند وعنوانالخادم واعتمادسياسةالمحتوى/الخصوصيةوالاحتفاظ.
لا توجدواجهاتتعديلأوحذف ضمنالنطاق. التطبيقلاينشرنصًاقانونيًا غيرمعتمد،
والواجهةمبدئيةللمرحلةالأولى؛ المراجعةالبصريةالنهائيةومطابقةالأصوللاحقًا.
