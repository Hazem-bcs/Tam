## النطاق والملكية

features/active_trip/** واختباراتها وحزمة docs/api/active_trip/ والتسليم.
المشرف يملك تعديل Trip المشترك وحالاته وcodec وMockTripStore، وربط
app/router/DI/config وHome/Ride/Trips ونواتج الترجمة واختبارات التكامل.
تبقى المصادقة والرقم وOTP والثيم والمنصات والعناوين كما هي.

حالات المورد: scheduled -> requested -> confirmed -> driver_en_route ->
driver_arrived -> in_progress -> completed؛ requested -> no_driver،
والإلغاء متاح حتى driver_arrived شاملًا ويتوقف عند بدء الرحلة.
الانتقالات مصدرها الخادم/محاكاة البيانات، وليست أزرار عميل لتعيين السائق
أو بدء الرحلة أو إنهائها. no_driver نهائية، والطلب مجددًا ينقل الموقعين
إلى سعر جديد ومعرف جديد. لا رسوم إلغاء أو تغييرات مال مخترعة.

Trip يملك live details اختيارية (إصدار/تواريخ/سائق/مركبة/موقع/ETA)،
وMockTripStore يحدّث الحالة والبيانات ذريًا بإصدار متزايد؛ لا مجموعة رحلات
أخرى أو حالة متنافسة. تبقى قراءة بيانات W1 القديمة دون live ممكنة.
يتابع محرك محاكاة مملوك للتطبيق الرحلات حتى عند إغلاق صفحة المتابعة،
ويحوّل المجدولة عند الموعد أثناء تشغيل التطبيق ويستدرك عند الاستئناف.
تُمسح الجلسة ويُغلق المحرك والاشتراكات. لا وعد بتنفيذ خلفي بعد إغلاق التطبيق.

تُعرض بطاقة السائق/المركبة والتفاصيل ومسار توضيحي ومراحل الرحلة، مع
حالة اتصال وموقع قديم وقراءة أحدث مورد عند إعادة الاتصال/استئناف التطبيق.
تحمي الإصدارات وهوية الطلب من ردود متأخرة. إلغاء غير محسوم يعاد بأمان
للمعرف نفسه، ولا يفتح طلبًا بديلًا قبل حسمه. الإلغاء من طلباتي ينعكس فورًا.
الدخول بعد الحجز إلى المتابعة، ومدخل من Home وتفاصيل طلباتي، واستعادة
الرحلة الحالية من المستودع. لا نقل state في route.extra كمصدر حقيقة.

## البيانات والتسليم

ACTIVE_TRIP_DATA_MODE يرث DATA_MODE؛ API محمي للضيف/localAccess ويفشل
بوضوح دون fallback. سيناريو المحاكاة المركزي success/no_driver/disconnect،
بساعة ومدد قابلة للحقن؛ fixtures اصطناعية في data/mock فقط.
GET /trips/current وGET /trips/{id}/live، وإعادة استخدام POST /trips/{id}/cancel
بلا endpoint إلغاء منافس. polling مقترح مع إصدار متزايد؛ لا فرض WebSocket.
حزمة عقد عربي v1 وPostman v2.1 وأمثلة/fixtures متوافقة وREADME.
