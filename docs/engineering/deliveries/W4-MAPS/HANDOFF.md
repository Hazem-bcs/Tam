## ما تم تسليمه

عارض flutter_map لبلاطات raster XYZ من عنوان صريح، تكبير وتحريك وعلامات
ونسبة OSM مع رابط الحقوق عند ضغط المستخدم. اختيار نقطة ووصف يدوي وبحث
وGPS بقراءة واحدة عند الطلب. مداخل في الانطلاق والوجهة والعنوان المحفوظ؛
خريطة الرحلة الجارية تستخدم Geometry الخادم وعلامة السائق الصالحة.
لا مسار مخترع عند فشل الخدمة، ولا تغيير لسعر الحجز من خريطة المعاينة.

Domain بلا SDK؛ HTTP وGeoJSON وGPS وفتح الحقوق في Data، واعتماديات
وإعدادات مركزية. لا Bearer أو cookies لخادم البلاطات أو اتباع redirect،
ولا خدمات خرائط عامة أو fallback تشغيلي. الحجوزات تبقى mock، وسلوك Auth
والدخول المؤقت محفوظ. أصلحت المراجعة سباق الوصف أثناء GPS ونتائج البحث
بعد اختيار النقطة ورمز ROUTE_NOT_FOUND، وأضافت اختبارات عدم التسرب بعد الخروج.

العقد [maps-v1](../../../api/maps/maps-v1.md) و[إعداد الربط](../../../api/maps/README.ar.md)
والأمثلة وPostman مستقل؛ التجميعة المعتمدة 15 مجلدًا و62 مثال طلب، وحالتها
BACKEND_HANDOFF_PROPOSAL. نسخة سطح المكتب المحدثة:
`/home/hazem/Desktop/Tam-Customer-API-v1.postman_collection.json`.

## حدود التسليم

أكد المستخدم أن الخدمات غير جاهزة: لا نشر خادم أو تنزيل بيانات منطقة.
MAP_TILES_URL_TEMPLATE وMAP_API_BASE_URL فارغان افتراضيًا. ظهور الشوارع
والبحث والمسارات الحية ينتظر توفير عنوانَي HTTPS الخاصين واختبار التغطية
والدقة وTLS/CORS. صورة configured-renderer-fixture.png بيانات اختبار فقط.
GPS على المحاكي يعيد موقع المحاكي، وليس إثبات دقة جهاز حقيقي.
iOS مُهيأ ساكنًا ولم يُبنَ لغياب macOS/Xcode. HTTP المحلي يحتاج تهيئة
المنصة كما في README؛ HTTPS هو مسار الربط المعتمد.
الواجهة مبدئية ضمن المرحلة الأولى؛ الصقل النهائي مستقل. لا push أو main
أو GitHub Actions؛ الدمج والحفظ محليان.
