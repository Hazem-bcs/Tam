## السلوك والمصدر الواحد

الحجز يفتح المتابعة بالمعرف فقط. مدخل Home يستعيد current، وتفاصيل طلباتي
تفتح متابعة المعرف نفسه. الحالة والبيانات في Trip/MockTripStore ذاتهما؛
لا قائمة رحلات ثانية. live تضم revision وupdatedAt/statusChangedAt والسائق
ومركبته وموقعه وETA. updateLive يقارن الإصدار المتوقع ويحدث الحالة والبيانات
ذريًا؛ لا يبدل هوية الحجز أو سعره. current يفضل النشطة غير المجدولة ثم أقرب موعد.

الحالات: scheduled/requested/confirmed/driverEnRoute/driverArrived/inProgress/
completed/cancelled/noDriver. active يشمل الرحلات القادمة والجارية فقط.
محرك Data يحاكي أحداث السائق تلقائيًا؛ لا أزرار راكب لتعيين السائق أو
وصوله أو بدء/إنهاء الرحلة. يدعم success/no_driver/disconnect، بساعة ومدد
محقونة. يبدأ المجدولة عند موعدها، ويستدرك الزمن بعد العودة، ويستمر عند
إغلاق صفحة المتابعة. لا تنفيذ خلفي بعد إغلاق عملية التطبيق أو حفظ دائم.

الإلغاء متاح حتى driverArrived وينتهي عند inProgress. الإلغاء من طلباتي
يحدّث live وإصدارها ويمسح الموقع وETA ويوقف تقدم الرحلة. التكرار آمن،
وفقد الرد يحتفظ بالمعرف ويمنع بديلًا من شاشة المتابعة حتى حسم القراءة
أو إعادة الإلغاء نفسه. لا رسوم مخترعة أو إعادة استخدام quote قديم عند noDriver.
الطلب الجديد ينقل الموقعين فقط، ويعيد التسعير ويبدأ فوريًا بمعرف جديد.

Polling كل5 ثوانٍ مع invalidation اختياري واستعادة عند resumed. الحالة
المحفوظة تبقى عند فشل القراءة مع تنبيه وإخفاء ETA. موقع أقدم من30 ثانية
يبقى آخر موقع معروف مع تنبيه، ولا يعتبر HTTP الناجح دليلاً على حداثة GPS.
snapshot غير متسق أو بمعرف آخر أو إصدار أقدم لا يكتب فوق الحالة الأحدث.
قراءة قديمة بدأت قبل إلغاء لا تعيد الحالة السابقة. المحرك لا ينهار أو
يرجع الحالة للخلف عند تراجع ساعة الجهاز.

## البنية والتكامل

Domain بلا Flutter/JSON/منصات. ActiveTripRepository يعيد Trip وفشلًا
مجاليًا، والـcodec الصارم في Data. API غير الجاهز يفشل دون fallback.
ACTIVE_TRIP_DATA_MODE يحرس current/details للضيف وlocalAccess مستقلًا عن
وضع طلباتي والحجز. ACTIVE_TRIP_MOCK_SCENARIO يقرأ مركزيًا في AppConfig
ويُفسر عند تركيب Mock repository؛ لا fixtures أو mode switch في UI/Cubit.

محرك المحاكاة مملوك لـTamApp ويغلق مؤقته واشتراكه، ويصفر failure seams
عند الخروج؛ بيانات الجلسة تمسح من المصدر المشترك. Cubit يملك polling
واشتراكه ويغلقهما، وتربط هوية Provider بالمعرف والمستودع. get_it يسجل
factory محقونة، والساعة تمر من تركيب التطبيق للمصدر وCubit عند الاختبار.
حُدّثت اختبارات الحجز السابقة لتفتح تفاصيل الطلب بعد شاشة المتابعة الجديدة،
مع الاحتفاظ بفحوص الربط السابقة. ساعة test harness ثابتة افتراضيًا لتجنب
اعتماد الاختبارات القديمة على سرعة الجهاز، وتُحرّك صراحة في اختبار المتابعة.

رُفع TripRoute وtrip_display إلى shared لمسؤوليتهما المشتركة بين الميزتين،
وفُصل TripDetailsActions ليبقى ملف الصفحة مركزًا. الملفات الجديدة المكتوبة
يدويًا أقل من300 سطر، دون ضغط تنسيق أو abstractions تمريرية.
الثيم والتوكنز وTam controls والترجمة ARB مركزية، وRTL/LTR والخط الطبيعي
والتمرير محفوظة. المسار رسم توضيحي وفق إحداثيات النموذج، وليس SDK ملاحة.
بطاقة السائق تفتح بياناته ومركبته وتقييمه ولوحته، ببيانات اصطناعية معلنة.
