## التغييرات المشتركة

TamApp يملك مستودع الإشعارات ويختار mock/API مركزيًا، ويحقن المستودع نفسه
إلى الصندوق وواجهة عداد Home. أُزيل المستودع العام من entry. Cubit الشارة
يلغي اشتراكه ويرفض نتيجة count قديمة بعد تحديث أحدث، ويعرض العدد كغير معلوم
عند فشل الخدمة دون mock fallback. يُعاد بناء الشارة وحدها عند تغير العدد.

عند نهاية الجلسة تُعاد الإعدادات إلى defaults، وتمسح الحجوزات التي أنشأها
المستخدم ومفاتيح idempotency. تُستعاد فقط fixtures اصطناعية مترابطة للرحلات
والإشعارات؛ لا تبقى بيانات الشخص السابق، ولا يشير إشعار seed إلى رحلة
محذوفة. clear() العامة للمخزن تظل تفرغ الكل لمن يطلبها صراحةً، بينما
resetSession() يعيد seed المحقون عند الإنشاء. الموارد تُغلق مع مالك التطبيق.

ثبتت اختبارات تكامل حقيقية عبر TamApp/GoRouter وواجهات الميزات: الحجز
والظهور بالقائمة والإلغاء وإعادة التسعير، ووجهة إشعار الرحلة وتحديث الشارة،
والخروج ثم الدخول بالرقم نفسه/رقم آخر/ضيف. لا تتغير AuthStatus إلى
مصادقة باكند، ولا يُنشأ token أو user موثق بسبب هذه العمليات.

## المتابعة

تُقبل الدفعة في المرحلة الأولى بعد سلامة المراجعة والفحوص المجمعة، مع
واجهات مبدئية وفق الاتفاق. فروق Home/الحجز/طلباتي/الإشعارات/الإعدادات
موثقة في تقاريرها وتُنقل للمرحلة الثانية؛ ليست مانعًا وحيدًا للدمج الآن.
لا يعني اكتمال هذه الدفعة اكتمال بقية التطبيق: العناوين والجدولة والرحلة
الجارية والمحادثة وحالات الإنهاء/التقييم/الدعم تحتاج بطاقات وعقود مستقلة.
