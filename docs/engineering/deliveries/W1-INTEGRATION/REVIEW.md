### نتائج سليمة

- أزيل المستودع العالمي من notifications_entry. يملك TamApp مستودع Mock واحدًا بعمر التطبيق، ويختار صراحةً Unavailable في API؛ لا fallback للمحاكاة.
- الراوتر يحقن المستودع نفسه للصندوق ولمصدر عداد Home؛ لا عداد مستقل أو رقم مثبت في الصفحة.
- resetSession يعيد seed immutable ويمسح failure plan وينشر العدد الصحيح؛ dispose يغلق stream. مالك التطبيق يستدعي reset عند الخروج وdispose عند انتهاء التطبيق.
- HomeUnreadCountCubit يشترك قبل قراءة العدد، ويستعمل revision لإسقاط الاستجابة القديمة بعد حدث أو خطأ أو طلب أحدث. الإغلاق يلغي الاشتراك ويهمل النتائج المتأخرة. حالتا API failure/close واختبار سباق حدث مقابل count موجودة وتنجح.
- اختُبرت حالتان إضافيتان خارج المستودع: خطأ stream أثناء الطلب ثم نجاح قديم، وطلبان يخطئ أحدثهما ثم ينجح الأقدم. كلاهما نجح؛ ظل العدد unknown ولم يقع خطأ asynchronous غير معالج، وحدث لاحق أعاد العدد وإغلاق Cubit أزال المستمع.
- resetSettingsFeatureSession مربوط في TamApp عند signedOut بعد جلسة مدخلة وعند dispose، كما طُلب في مراجعة Settings. اختبارات Home logout تغطي الرقم نفسه ورقمًا مختلفًا والضيف؛ لا تسرب للاسم أو التفضيل، ولا إنشاء هوية Auth وهمية.
- اختبار الرحلة يستخدم الواجهة للحجز، يتحقق من مصدر الرحلات المشترك، ثم الإلغاء وإعادة الطلب بالمواقع وتسعير جديد وعدم حمل confirmedTrip قديمة. اختبار الإشعار قبل الخروج يفتح الرحلة المشتركة ويحدث شارة Home. عيب إعادة الدخول المذكور أعلاه كان الفجوة الوحيدة التي ثبتت.
