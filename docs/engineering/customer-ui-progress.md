## آلية العمل المعتمدة

بقرار المستخدم، [المرحلة الأولى](development-phases.md) للبنية وDomain/Data
والسلوك وعقود API والمحاكاة والتكامل بواجهة مبدئية قريبة من الهدف. نعود
بعد اكتمال تدفقات التطبيق صفحةً صفحة لتحسين التصميم في المرحلة الثانية.
فروق الشكل وحدها لا تمنع الدمج الآن؛ الثيم والتجاوب وسلامة الاستخدام
والعقود وعزل الجلسة لا تؤجل. هذه الأرقام لا تعني جاهزية النشر.

## ما أصبح في النسخة المجمعة

- أساس واحد للثيم والمكونات والإعدادات والترجمة والتنقل وحراسة الوصول.
- Auth: رقم وOTP وحالة الجلسة والضيف والخروج؛ الافتراضي دخول محلي برقم
  سوري صحيح دون OTP حتى ربط الباكند، دون user/token مصادقة اصطناعي.
- Home: الخدمات والترويج ومدخل الحجز والتنقل، وشارة من مصدر الإشعارات نفسه.
- Ride: اختيار المواقع والفئة وتسعير وتأكيد محاكى مع idempotency.
- Trips: القائمة والفلاتر والتفاصيل والإلغاء وإعادة الطلب بسعر جديد.
- Notifications: القائمة والترقيم والتحديث والقراءة/الكل والوجهات الآمنة.
- Settings: اسم الحساب وتفضيل الإشعارات واللغة والخروج، مع إعادة بيانات
  الجلسة عند انتهائها. اللغة محلية لهذه العملية، لا حفظ دائم بعد تشغيل جديد.
- العناوين: قائمة/إضافة/تعديل/حذف واختيار عنوان محفوظ للانطلاق والوجهة.
- الجدولة: فوري/مجدولة من30 دقيقة إلى7 أيام، مع وقت خدمة UTC+03:00 ونقل UTC،
  وسعر مرتبط بالموعد، وظهوره في طلباتي وحفظه عند الإلغاء؛ إعادة الطلب فورية.
- حزم API العربية وPostman والأمثلة لـAuth والميزات الخمس والعناوين والجدولة؛ لا HTTP حي
  للميزات الجديدة بعد، وAPI غير الجاهز لا يسقط إلى mock بصمت.

**5/5 ميزات الدفعة الأولى مدمجة ومعتمدة وظيفيًا ضمن نطاقها.** ليس هذا
اكتمال المرحلة الأولى لكل التطبيق؛ ما زالت ميزات الدفعة التالية مطلوبة.

## متابعة المرحلة الثانية

Home تحتاج البانر وصور الخدمات وترتيب المحتوى؛ الحجز يحتاج تركيب الخريطة
واللوحة السفلية وصفوف الفئات؛ طلباتي تحتاج كثافة القائمة وأقسام التفاصيل
المتفق عليها؛ الإعدادات والإشعارات تحتاج ضبط الكثافة والمسافات والخط
والعناصر وفق الصور. العناوين تحتاج تركيب الخريطة واللوحة السفلية والتفاصيل
البصرية وفق UI-02. تبقى التقارير التفصيلية في مجلد deliveries/ للمراجعة.

العناوين والجدولة مدمجتان محليًا؛ لم تُرفعا أو تدمجا إلى main أو تشغّلا
Actions. الطعام/التسوق والمحفظة والدفع الإلكتروني والكوبونات
تحتاج نطاق عميل واضحًا، ولا نستعير تصميم محفظة السائق كبديل عنها.
